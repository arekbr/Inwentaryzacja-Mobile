### Deep findings (≥80 confidence, 13 unique)

#### [C-D01] CameraIntent `s_instance` — race + brak invariant ⚠ **CRITICAL**
- **Files:** `CameraIntent.cpp:12-24, 67, 81`
- **Confidence:** 88/100 (3 agentów: Ownership, Threading, API)
- **Finding:** Plain pointer (nie atomic), zapis z głównego wątku, czytany z JNI binder w `nativeOnPhotoCaptured`. Na ARM Android brak memory barrier = realny reordering hazard. Konstruktor nadpisuje bez `Q_ASSERT(s_instance == nullptr)`.
- **Mitigation:** `std::atomic<CameraIntent*> s_instance` z acquire/release, `Q_ASSERT` w ctorze, `Q_DISABLE_COPY_MOVE`.

#### [C-D02] `saveExhibit` base64 całego zdjęcia w RAM — OOM ⚠ **HIGH**
- **File:** `ApiClient.cpp:240-256`
- **Confidence:** 95/100
- **Finding:** `file.readAll().toBase64()` na 8 MB JPEG → ~11 MB base64 → kopia w QJsonDocument = ~25-30 MB transient heap. Na low-end Android (foreground budget <256 MB) realny OOM-kill.
- **Mitigation:** Switch na multipart (jak `sendMultipartPost`), Qt streamuje QFile bez buforowania.

#### [C-D03] `sendMultipartPost` emituje `identifyError` dla wszystkich callerów ⚠ **HIGH**
- **File:** `ApiClient.cpp:101-110`
- **Confidence:** 95/100
- **Finding:** Helper jest endpoint-agnostic, ale przy `QFile::open()` failure hardcodowo `emit identifyError`. Jeśli ktoś przejdzie przez ten helper z innym endpointem — error zniknie w czeluści.
- **Mitigation:** `std::function<void(const QString&)> onError` jako parametr.

#### [C-D04] `formatNetworkError` konsumuje `reply->readAll()` — destrukcyjny side effect
- **File:** `ApiClient.cpp:30`
- **Confidence:** 90/100
- **Mitigation:** Rename na `consumeAndFormatNetworkError()` lub `peek(4096)` zamiast `readAll()`.

#### [C-D05] AppSettings nie waliduje `apiUrl`
- **File:** `AppSettings.cpp:20-26`
- **Confidence:** 90/100
- **Mitigation:** `QUrl url = QUrl::fromUserInput(value); if (!url.isValid() || (scheme != "http" && != "https")) emit apiUrlInvalid()`.

#### [C-D06] `formatNetworkError` default branch traci kontekst
- **File:** `ApiClient.cpp:67-70`
- **Confidence:** 87/100
- **Mitigation:** Zawsze dołącz `reply->errorString()` + `int(err)` w default. Loguj triple przez `qCWarning`.

#### [C-D07] Brak walidacji `photoPath` — path traversal
- **Files:** `ApiClient.cpp:101, 168, 245`
- **Confidence:** 82/100
- **Mitigation:** Allowlist root (`QStandardPaths::CacheLocation`), `QFileInfo::canonicalFilePath()`, odrzuć symlinki, validate magic bytes (FFD8FF).

#### [C-D08] `AppSettings::apiUrl()` Q_PROPERTY READ wykonuje I/O każdy call
- **File:** `AppSettings.cpp:14-18`
- **Confidence:** 80/100
- **Mitigation:** `mutable QString m_apiUrlCache` populowany w ctorze.

#### [C-D09] Token API tracony przy Android process kill — UX
- **File:** `AppSettings.cpp:6-12`
- **Confidence:** 80/100
- **Mitigation:** Albo Android Keystore/EncryptedSharedPreferences, albo explicit "Token wymagany" przy 401 po restart.

#### [C-D10] Powtarzalny boilerplate auth+timeout w 5 endpointach
- **File:** `ApiClient.cpp:128, 194, 221, 252, 295`
- **Confidence:** 88/100
- **Mitigation:** Helper `applyAuth(QNetworkRequest&)` + `prepareRequest(path, timeout)`. -80 LoC.

#### [C-D11] Async signal handlers fire on destroyed pages — brak request token
- **File:** `ApiClient.cpp:169, 248` (synchroniczne emit early errors)
- **Confidence:** 85/100
- **Mitigation:** `QMetaObject::invokeMethod(this, ..., Qt::QueuedConnection)` standardize.

#### [C-D12] `Bearer ` header buduje 5× ten sam QString — minor perf
- Jak D-10 (overlapping).

#### [C-D13] `sendMultipartPost` parent chain `multi → reply` brittle
- **File:** `ApiClient.cpp:112-132, 174-198`
- **Confidence:** 82/100
- **Mitigation:** `std::unique_ptr<QHttpMultiPart>` aż do `release()` po `m_nam->post`.

### Deep findings (≥80 confidence, 16 unique)

#### [Q-01] **`model.model` role collision w ListView delegate** ⚠ **HIGH** (5 agentów)
- **File:** `ExhibitListPage.qml:31-37, 178, 208`
- **Confidence:** 95/100
- **Mitigation:** Rename rolę `model` → `device_model` w `itemsModel.append({...})`. `required property string device_model` w delegate. `pragma ComponentBehavior: Bound`.

#### [Q-02] `stack.currentItem.title` — type error
- **File:** `Main.qml:36, 50`
- **Confidence:** 92/100
- **Mitigation:** `readonly property Page currentPage: stack.currentItem as Page`.

#### [Q-03] `inputItem.hints` przez `parent.parent` — fragile cross-tree reach
- **File:** `EditExhibitPage.qml:53, 82`
- **Confidence:** 95/100
- **Mitigation:** `id: row` na FormRow, `inputMethodHints: row.hints`. `property int hints: Qt.ImhNone`.

#### [Q-04] CameraIntent singleton — multi-page race ⚠ **HIGH**
- **Files:** `CameraPage.qml:12-23, 154-157`, `SimilarPage.qml:14-23, 202-205`
- **Confidence:** 90/100
- **Mitigation:** `Connections { enabled: StackView.status === StackView.Active; ... }`.

#### [Q-05] Async signal handlers fire on destroyed pages — brak request token
- **Files:** `ExhibitDetailPage:24-27`, `EditExhibitPage:42-46`, `ExhibitListPage:19-44`
- **Confidence:** 88/100
- **Mitigation:** Per-request UUID token w `ApiClient`, page filtruje przed apply.

#### [Q-06] Image bez `sourceSize` — RAM/GPU waste ⚠ **HIGH**
- **Files:** `ExhibitListPage:151-160`, `SimilarPage:48-58, 145-154`, `ExhibitDetailPage:44-57`, `EditExhibitPage:94-103`, `CameraPage:72`
- **Confidence:** 90/100
- **Mitigation:** `sourceSize: Qt.size(128, 128)` (2× retina) na list thumbs, `Qt.size(144,144)` na similar.

#### [Q-07] ListModel z 1870 base64 thumbnails — memory ceiling ⚠ **HIGH**
- **File:** `ExhibitListPage.qml:17, 31-37`
- **Confidence:** 92/100
- **Mitigation:** Krótkoterminowo: cap 200 ostatnich z prune. Długoterminowo: C++ QAbstractListModel + lazy URL thumbs.

#### [Q-08] Brak `reuseItems: true` na ListView
- **File:** `ExhibitListPage.qml:115-125`
- **Confidence:** 87/100
- **Mitigation:** `reuseItems: true` + `ListView.onPooled: source = ""` na Image.

#### [Q-09] `onContentYChanged` per-pixel polling
- **File:** `ExhibitListPage.qml:128-132`
- **Confidence:** 85/100
- **Mitigation:** `onAtYEndChanged` lub `footerItem` sentinel z BusyIndicator.

#### [Q-10] Brak handlera Image error — silent failures
- **Files:** 4 strony (wszystkie poza CameraPage)
- **Confidence:** 92/100
- **Mitigation:** `onStatusChanged: if (status === Image.Error) { /* placeholder + log + statusLabel */ }`.

#### [Q-11] `statusLabel.X = ...` ad-hoc global anti-pattern
- **Files:** `CameraPage`, `SettingsPage`, `EditExhibitPage`, `SimilarPage`
- **Confidence:** 82/100
- **Mitigation:** Adoptuj ExhibitListPage pattern: `property string statusText` + binding. Albo wydziel `StatusBar.qml`.

#### [Q-12] `appSettings.apiUrl` two-way binding loop risk
- **File:** `SettingsPage.qml:69-70, 112-113`
- **Confidence:** 80/100
- **Mitigation:** `onEditingFinished` zamiast `onTextChanged`.

#### [Q-13] Brak `pragma ComponentBehavior: Bound` w żadnym pliku
- **Files:** wszystkie 7
- **Confidence:** 88/100
- **Mitigation:** Dodaj na delegate-bearing pliki. Wymaga `required property` deklaracji.

#### [Q-14] `property var backendInfo` — undefined-rendering risk
- **Files:** `Main.qml:68`, `ExhibitDetailPage:11-12`
- **Confidence:** 82/100
- **Mitigation:** `readonly property string version: backendInfo?.version ?? "?"` derived properties. Nigdy nie assign `({})` na error — `null` z optional chain.

#### [Q-15] EditExhibitPage — brak IME-aware bottom margin ⚠ **HIGH UX**
- **File:** `EditExhibitPage.qml:87-216`
- **Confidence:** 84/100
- **Finding:** Brak ScrollView (per landmine #1) + brak IME margin = gdy soft keyboard otwarty, Save button untappable.
- **Mitigation:** `anchors.bottomMargin: Qt.inputMethod.visible ? Qt.inputMethod.keyboardRectangle.height : 0`.

#### [Q-16] ToolBar `topPadding: 60` raw pixels
- **File:** `Main.qml:16`
- **Confidence:** 82/100
- **Mitigation:** `Screen.devicePixelRatio * 24` (24dp Android baseline) + notch heuristic.
